# Working context

Everything a fresh session needs to be as oriented as the session that set this repo up. Read alongside `brief.md` (the task and payload) and `jd.md` (the role).

## The task in one paragraph

A dashboard for a wealth adviser's book of business. Two parts: a stacked bar chart over Feb 2024 - Jan 2025, and a per-month table with rows that expand one level at a time (company > branch > adviser > acquisition channel). React and TypeScript, data served by a Node REST API, loading and error states handled, keyboard-operable expansion, hierarchy exposed to assistive tech, tests for expand/collapse and for how data maps into the chart, nothing broken at 375px, README with assumptions and open questions. Budget 6-8 hours.

## What is already decided

- **Frontend:** Vite, React 19, TypeScript strict, `createBrowserRouter`. The dashboard is `/dashboard/:year`; `/` and `/dashboard` redirect in a loader to `/dashboard/2024`, replacing the entry. A four-digit year starting with 1 or 2 always renders, including one with no data; `/dashboard/abc`, `/dashboard/0024` and `/dashboard/3000` are not found rather than redirected, so a typo stays visible, and none of them makes a request. Tailwind v4 and shadcn/ui for the two data components, CSS modules for the page shell, tokens in `apps/web/src/index.css`. Same shape as the employer's own app.
- **Page and cards:** the page is #F9F9F9 and that both blocks keep a white 8px-radius card wrapper so they can be reused over any surface, and that the table card pads 8px inside its radius so the rail and the focus ring are not clipped by the rounded corners.
- **Typography:** Inter Variable Latin subset vendored under `apps/web/public/fonts/inter-latin-variable.woff2` and preloaded from `apps/web/index.html`. Self-hosting without npm dependencies avoids third-party requests and off-screen font loading prevents layout shifts on first paint. Month labels use `formatMonthShort` ("Feb", "Jan") below sm and `formatMonthLabel` ("Feb 2024") at sm and above, rendered with separate spans so the unused label stays out of the accessibility tree.
- **Table:** `TreeGrid`, a native `<table role="treegrid">` with the WAI-ARIA APG rows-first keyboard model. Not Accordion or Collapsible over divs, not TanStack Table. Rows are the only focus target; cells are not, which is a stated deviation from APG. The chevron is pointer only for the same reason: it takes no focus, the row keeps DOM focus after a pointer click, the focus-visible ring is reserved for keyboard interaction via `{ focusVisible: false }`, and Enter on a row selects and never toggles. Expansion is local state, selection is `?node=<id>`. The visible row list comes from `flattenVisible` in `apps/web/src/lib/tree.ts`, a pure function, so the levels, the sibling counts and the kind of each row can be unit tested without a browser. On small screens below sm, the table increases density with text-[13px], h-12 rows, px-1.5 cells, custom indent [--row-indent:12px], short month headers, and a sticky name column pinned at left 0 with z-10 and bg-card mirroring the row hover band. The sticky name column uses `w-[clamp(160px,48vw,296px)]` across header and cell, keeping its width constant regardless of expansion depth. Row names carry `min-w-0 flex-1 truncate` with a title attribute for pointer fallback while the full text remains in the DOM and the accessibility tree. Chevron buttons and leaf placeholders reduce to 24 by 24 pixels (`h-6 w-6 sm:h-8 sm:w-8`) to preserve text space while meeting the target size floor.
- **Avatars:** a 20px circle with the adviser's initials on adviser rows, coloured with the same `--chart-N` token that adviser's series uses in the chart, so a legend swatch and a row circle match. The circle is the token mixed 25% into the card. The mix is what makes one ink work: at full strength white on `--chart-1` (#B29DF8) is 2.32:1 and `--foreground` on `--chart-3` (#A75E6E) is 4.21:1, while the mixed swatches read between 13:1 and 16:1 against `--foreground`. The payload has no image field, so the design's photograph is not served.
- **Chart:** `MonthlyChart`, shadcn Chart over Recharts 3. Recharts 3.8 keeps its keyboard index on blur, so a second Tab into the chart reopened no tooltip and continued from the old month, and v3 has no controlled active index, so `MonthlyChart` owns the focus model: focus enters on the first month, resets when it leaves, arrow keys move between months (ArrowLeft/ArrowRight and ArrowUp/ArrowDown), and the tooltip is driven by a mouse move at the tick position so the library's cursor, tooltip, flipping and animation stay the library's. It stacks the selected node's immediate children: branches, then advisers, then channels, and a single series for a leaf. Stacked bars use a custom Bar shape rendering Recharts Rectangle with `radius={[4, 4, 0, 0]}` on desktop and `radius={[0, 4, 4, 0]}` in the narrow vertical layout on the topmost segment of each month chosen by `toTopSeries`, so the corners animate with the growing columns and months where the top series is zero keep rounded end corners. Below 640px, the chart turns horizontal (layout="vertical") with the numeric axis along X and category month labels along Y with width 40 and height 440px (390px at sm), CartesianGrid flips to vertical gridlines, maxBarSize is 20px (88px desktop), and the legend renders outside the plot as a flex-wrapped HTML list inside the figure. The visible title and caption were replaced by the scope trail above the chart, which provides the accessible name for the figure, while the month labels follow the year in the route. The treegrid is the accessible alternative. The mapping from a node to chart data lives in `apps/web/src/lib/chart.ts` (`toSeries`, `toRows`, `toDomain`, `toTopSeries`, `scopeTitle`), so the brief's "data maps into the chart" test is a unit test and not a browser test. The axis maximum is the largest stacked month, rounded up to the next hundred above a hundred and to the next ten below it: 400 for the company, 300 for Branch 1, 40 for Anna Blackwood.
- **Header and scope trail:** the page title is constant (`h1` "Clients") and names the section, with the fiscal period beside it appearing once. The chart's visible title and caption were replaced by `ScopeTrail`, a `<nav aria-label="Chart scope">` breadcrumb above the chart. The trail shows the path of names only with no breakdown suffix: ancestors are clickable buttons selecting that node, the current item carries `aria-current="location"`, and activating an ancestor from the keyboard moves focus to the new current item while pointer clicks do not. The current crumb label (the node name) serves as the accessible name for both the figure and the chart container via `labelledById`.
- **Chart palette:** `--chart-1` to `--chart-3` are the design colours #B29DF8, #F4BEB4 and #A75E6E. `--chart-4` and `--chart-5` are a sky (#7EC8E3) and a sage (#8BC48A); the design fixes three and Branch 1 needs five, because it stacks five advisers and the legend shows all five at 16px.
- **Selection:** a row click selects and the chart remaps. A chevron click expands without selecting, a double-click does both. The URL records the selection with `replace`, so a drill is shareable and Back leaves the dashboard. The selected row is marked by a 3px ink rail at the row's left edge with a transparent resting state and the name weight unchanged, and the hover band applies to the selected row as well.
- **Backend:** Express, in the same repo, deliberately thin. `GET /api/dashboard/:year` returns the payload object itself; a malformed year (not four digits starting with 1 or 2) is 400 `{"error":"Invalid year format"}` and a year with no data is 404 `{"error":"Data not found for the given year"}`; `GET /api/health`. One route, because the chart can be remapped to any node and the whole tree is twelve nodes.
- **Contract:** one Zod contract in `shared/`, holding the four source schemas, their types and a `TreeNode` union. The server validates what it sends, the client parses what it receives, and no interface is duplicated. There are no response schemas: the wire shape is the payload. No month labels either: the wire carries twelve bare numbers and the fiscal calendar is presentation. `Company.branches` is optional alongside `employees` and `channels`: a node without children is a leaf, and the client never assumes three branches. The mock payload sits next to the contract on its own entry point, `@nevis/shared/payload`, so the API serves it and the web tests read the same tree instead of keeping a second copy of the numbers.
- **Client data:** SWR, one key per year, in-memory cache, no context for data. The revalidation switches stay at SWR's defaults, so the page refetches on focus, on reconnect and on every mount of the key, because the payload can change server-side. `shouldRetryOnError` is a function that retries a 5xx and a request that never got an answer, never a 4xx and never a body the client could not read, because a response the server meant is final, and `errorRetryCount: 2` bounds the retries. A 404 is an empty state, not an error, so the fetcher keeps the status and the page branches on it.
- **Toolchain:** vitest for the pure modules, Playwright for the browser suite, Biome for lint and format, and Fallow for code analysis (dead code, duplication, complexity). `typescript-eslint` caps its peer range at TypeScript 6 and the repo is on TypeScript 7, so ESLint does not install. Biome parses TypeScript on its own. One `biome.json` at the repo root owns the style (two spaces, 100 columns, double quotes, semicolons) and the `organizeImports` assist; the shadcn components under `apps/web/src/components/ui` stay excluded. It has to be at the root: the editor's language server looks for a config at the workspace root and walks up, so a nested `apps/web/biome.json` was invisible to the editor, and Biome rejects a root config next to a nested one. Fallow runs in CI (`npm run analyze`) with default thresholds (cyclomatic 20, cognitive 15, unit size 60, CRAP 30.0); `.fallowrc.jsonc` excludes `components/ui/**`, `e2e/**`, and unit tests from health findings only, keeping dead-code and clone detection enabled.
- **Bundle splitting:** `codeSplitting.groups` in `apps/web/vite.config.ts` isolates `recharts` (~348 kB) and the shared `node_modules` (~438 kB) from application code (`index` ~24 kB, `MonthlyChart` ~9 kB), eliminating Vite's 500 kB chunk warning. The vendor group's test ends in a path separator, so `react` matches `react` and `react-dom` but not `react-redux`, which follows recharts into the chart chunk. `MonthlyChart` is behind a `React.lazy` boundary with a space-exact placeholder, so recharts is off the entry graph and the 404 and no-data pages download neither chunk. Route-level lazy loading is avoided so the loading skeleton mounts immediately on first render without waiting for route chunk downloads.
- **Header and loading state:** the page shell and the header render in one return in `Dashboard.tsx`, with only the content below the header conditional, so the `h1` DOM node survives the swap from loading to loaded and stays the LCP element. The header is in the DOM from the first paint, including during loading and during the error state. `LoadingState` and `ErrorState` no longer render a `main` element, so there is no nested landmark.
- **Chart placeholder:** `MonthlyChartPlaceholder` reserves the same box as the plot (`h-[440px] sm:h-[390px]`) and renders the same legend markup through `MonthlyChartLegend`, so the two occupy identical space and Cumulative Layout Shift stays 0 when the chunk arrives.
- **Treegrid row accessible name:** `<TableRow role="row">` carries `aria-label={row.name}` so the row's accessible name in the accessibility tree is strictly the node name ("Company", "Branch 1"). Without it, child elements including the chevron expand button leak into the row name, causing screen readers to announce "Collapse Company Company".
- **Fiscal calendar:** `apps/web/src/lib/period.ts` holds the twelve-month table, `formatMonthLabel`, `formatPeriod` and `currentFiscalYear`. February is first because the fiscal year says so; the year in the labels comes from the route.
- **Empty year:** `/dashboard/2025` renders a heading with the year, a form with a visually hidden label (`<label htmlFor="year" className="sr-only">Fiscal year</label>`), a fixed-width select (`w-56`) over 2000 to the current fiscal year and a Go button, and a link to `/`. The select always shows a disabled placeholder ("Select a fiscal year") and resets on every submit: it is an action, not a display of the current year. The range is valid years, not populated ones, so no endpoint is needed. A year change uses `push`. Browsers supporting `appearance: base-select` render the picker anchored under the control with styled options and the UA picker icon hidden, and the closed control centres its selected content with `align-items`; Firefox falls back to the native select popup.
- **Loading state:** The first paint renders the `role="status"` region named "Loading" immediately so assistive technology learns about it at once, under the header, which is already on screen. The decorative skeleton shapes mount only after a 200ms delay via `useDelayedFlag`, so a 404 or fast response never flashes a chart skeleton. When the response arrives, the skeletons unmount.
- **State pages:** `/dashboard/:emptyYear` and `*` (not found) use a centered shared shell (`StatePage`) with a decorative looping muted MP4 video (The Office clips), an intrinsic poster frame, and an accessible pause/play toggle button overlay. WCAG 2.2.2 requires a mechanism to pause moving content longer than five seconds, and `prefers-reduced-motion` suppresses autoplay, showing the poster frame until explicit user play. Because the state pages carry a decorative video with a poster frame, they have no separate placeholder.
- **Deploy:** none. The project runs locally with `npm run dev`; there is no hosted demo, so no CORS question, no base URL and no deploy pipeline. In dev, Vite proxies `/api` to the API port. Vite binds to the local network with `host: true` in dev and preview configurations, proxying `/api` to port 3000 so the dashboard can be tested directly from mobile devices on the same Wi-Fi.
- **Data:** the payload is the source of truth, served unchanged. It lives in `packages/shared/src/payload.ts`; `parsedDataMap` in `apps/api/src/data.ts` is a `Map` with one entry, FY2024, parsed once at module scope; `getData(year)` returns that tree or undefined. No projections, no corrections, no derived totals: the source query and filters are unknown, so a correction would be invented. Moving to a real database touches one file.

The API is a prop for this exercise, not the deliverable. Keep it small, spend the hours on the UI.

Three design issues to resolve in code and record in the README:

1. **The chart legend does not match the data.** It names Existing clients / New organic / New paid at company scale, but channels exist only under one adviser, where the bars top out at 38. The legend is illustrative. Resolved: the chart stacks the selected node's children, so those three names appear only when Anna Blackwood is selected.
2. **The design's bars drift from its own table.** The gridlines put 0.8px on a unit, and the bars read 262.5 for Sep, Oct, Nov and Dec where the table says 250, and 363.75 for Jan where the table says 350. The other months sit within two units of the table. Match the visual treatment rather than pixel positions.
3. **The design disagrees with itself on one cell.** Branch 1 reads 291 for Jul 2024 in the tree frame `0:1498` and 201 for the same cell in the table frame `1:2901`. The payload says 201, and 201 is the number that closes against the advisers, so the tree frame carries the typo.

## Data facts

Arithmetic in the payload, verified:

- Branch 1, Jul 2024 is 291 in the design's tree frame `0:1498` and 201 in the design's table frame `1:2901`; the payload says 201. 201 + 92 + 41 = 334, the company figure, so the payload is right and the tree frame has a typo.
- May 2024: branches sum to 279 (156 + 87 + 36), company says 301.
- Aug 2024: advisers sum to 216, branch says 214.
- Anna Blackwood's channels differ from her own row by 1 in May, June, July and September, and by 2 in August. Her 2 in August is the whole of the branch's 2-unit gap that month. Every other channel month matches, and every other adviser matches their branch.

Settled: the payload is served as given. The source query and filters are unknown, so correcting a cell would mean inventing a rule for which one is wrong. The mismatches are recorded in the README and nowhere else.

## Ideas worth building, in order of value

1. **Keyboard and screen-reader parity for the chart.** Not just the table: expose the same numbers through a companion data table or a focusable bar series with an accessible description. Almost no take-home does this and their interview bank asks about keyboard access to charted data. The focusable bar series is done: the chart is focusable once, focus always starts at the first month and resets when focus leaves, the arrow keys step through the months, and a polite live region announces the month with one line per series. The companion data table was considered and dropped: it was not in the design or the brief, the tooltip and the treegrid expose the same values, and a table that sits hidden in the DOM adds markup that no user sees.
2. **The loading and error states**, reached by intercepting the route in the browser suite. A query parameter that made the API answer 500 would put fault injection in the product path, and the slow case is one click away in the DevTools throttling dropdown. Done: the browser suite intercepts the route for both.
3. **Tests the brief names**, plus one for branches without employees and one for the chart mapping (payload values to segment totals and axis scale). Done: 66 unit cases and 40 browser specs.
4. **A data-quality note** in the README, with a UI decision behind it: a footnote, a tooltip, or a dev-only badge on inconsistent months.
5. **Formatting:** `Intl` for month labels and numbers, tabular figures in the table so columns align, and a horizontal scroll container for the table with a sticky name column rather than squeezed columns at 375px. The chart flips to a vertical layout below 640px instead of scrolling sideways.
6. **States:** empty depth, reduced motion, a slow response that resolves after the page moved on. The empty-year and not-found state pages honour reduced motion with a poster frame and provide a pause control.
